# M0. 실행 환경과 저장소 기반 — Lv1

## 목표

Docker로 MySQL과 Redis를 실행하고 Spring 애플리케이션이 두 저장소에 정상적으로 연결되는 상태를 만든다.

이번 M의 완료 시점에는 **아무 기능도 구현하지 않아도 된다.**
대신 이후 Lv2~Lv15를 실행할 수 있는 개발 기반이 안정적으로 준비되어 있어야 한다.

## 이번 단계에서 이해할 것

- Docker Image와 Container
- port mapping
- MySQL과 Redis의 역할 차이
- Spring datasource 설정
- Spring Data Redis 연결
- `spring.jpa.hibernate.ddl-auto=update`
- application.properties와 Docker 환경 변수의 역할 차이
- 재현 가능한 개발 환경

## 내가 설명할 수 있어야 함

### MySQL과 Redis를 둘 다 사용하는 이유는?

MySQL은 장기간 보존할 정형 데이터를 영속화한다.

Redis는 접속 상태, 캐시, Rate Limit처럼 빠른 접근과 만료가 필요한 임시 상태를 담당한다.

### application.properties와 docker-compose.yml의 역할은?

```text
docker-compose.yml
= 어떤 서버/DB 프로세스를 어떤 환경으로 띄울지 정의

application.properties
= 실행 중인 Spring이 그 외부 시스템에 어떻게 접속할지 정의
```

### `ddl-auto=update`는 무엇을 하는가?

Entity mapping과 DB schema를 비교하여 개발 환경에서 필요한 schema 변경을 적용한다.

과제 요구사항이므로 사용하지만 운영 환경에서 무조건 적절한 설정은 아니다.

### Dockerfile과 docker-compose.yml은 같은가?

아니다.

```text
Dockerfile
= 하나의 애플리케이션 이미지를 만드는 방법

docker-compose.yml
= 여러 container를 어떤 구성으로 함께 실행할지 정의
```

이번 Lv1에서는 MySQL과 Redis 실행 재현성이 핵심이므로 Compose가 직접적이다.
